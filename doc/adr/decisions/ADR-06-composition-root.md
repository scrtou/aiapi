# ADR-06 使用组合根替代业务 Service Locator

| 项 | 值 |
|---|---|
| 状态 | 已接受，迁移中 |
| 当前版本 | v3.0 |

## 决策

`AppContext`/`main.cc` 是唯一创建并连接具体服务的地方。Controller 持有 use case，use case 持有 port；业务代码不得调用项目自有 `getInstance()/instance()` 查找依赖。

允许的例外必须登记：第三方框架进程入口、无状态纯函数、进程级只读常量。例外不得持有线程、DB 连接或可变缓存。

## 增量迁移语义

“不做兼容层”指单个组件迁移完成后不保留新旧两套访问方式，不表示所有组件必须一个提交完成。

每个组件按以下顺序迁移：

1. 提取最小 port；
2. 现有类实现 port；
3. 在 AppContext 构造；
4. 修改一个完整调用闭包；
5. 删除该组件的单例访问器；
6. 增加 CI 禁止回归规则。

优先级：无生命周期 DB wrapper → 无线程状态服务 → 持有线程/队列的服务。后者必须遵守 ADR-08。

## 所有权

- 默认值成员或 `unique_ptr` 表达唯一所有权；
- 只有确实跨异步任务共享生命周期时使用 `shared_ptr`；
- 依赖参数优先引用或非拥有指针；
- 异步任务不得捕获生命周期不受保证的裸 `this`。

## 验收

- domain/application 中项目自有单例访问为 0；
- 生命周期对象全部由 AppContext 显式拥有；
- 每个已迁移组件只有一个构造路径；
- AppContext 有构造失败、重复 shutdown 测试；
- 停机顺序遵循 ADR-08。
